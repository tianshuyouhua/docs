# 任务对话

学会在任务执行过程中与 WorkBuddy 有效沟通，随时调整方向、补充信息、优化结果。

## 任务对话的价值

### 为什么需要任务对话？

传统工具：
- 一次性输入 → 等待结果
- 结果不满意 → 重新开始
- 缺乏过程控制

WorkBuddy 对话模式：
- 持续沟通 → 动态调整
- 实时反馈 → 及时纠偏
- 协作共创 → 优化结果

### 何时进行对话？

| 时机 | 示例 |
|-----|------|
| 任务开始前 | 确认理解是否正确 |
| 规划展示时 | 调整执行步骤 |
| 执行过程中 | 询问进度、提供补充信息 |
| 初步结果后 | 修改完善 |
| 最终结果后 | 迭代优化或开启新任务 |

## 任务开始前的对话

### 需求澄清

当 WorkBuddy 对需求不确定时：

```
WorkBuddy: "为了更准确地完成周报，能否告诉我：
1. 周报是提交给谁的？
2. 需要侧重哪些方面？
3. 有没有特定的格式要求？"

用户: "发给 CTO 看的，重点写技术进展，
      格式参考上周那份即可"

WorkBuddy: "明白了，重点关注技术进展，
      参考上周格式。开始执行。"
```

### 方案确认

展示执行计划并征求同意：

```
WorkBuddy: "针对您的需求，我计划这样执行：

步骤 1: 搜索行业最新动态（5 分钟）
步骤 2: 整理技术突破（8 分钟）
步骤 3: 撰写分析报告（10 分钟）
步骤 4: 生成可视化图表（5 分钟）

预计总耗时 28 分钟，有任何调整建议吗？"

用户: "步骤 2 可以简化，重点放在应用案例上"

WorkBuddy: "收到，调整后的计划：
..."
```

## 执行过程中的对话

### 进度查询

随时了解执行情况：

```
用户: "进度怎么样了？"

WorkBuddy: "已完成 2/4 个步骤：
✅ 数据收集完成
✅ 初步分析完成
⏳ 深度分析进行中（预计 8 分钟）
⏸ 报告撰写等待中

当前在分析用户留存率的影响因素"
```

### 中途调整

执行过程中随时修改：

```
场景: 正在生成产品文档

用户: "等等，目标用户群体需要调整，
      从'企业客户'改成'中小企业'"

WorkBuddy: "收到，已记录目标用户调整。
      重新分析中小企业需求特点..."

---

用户: "第三部分的产品定价先别写了，
      等老板确认价格后再补充"

WorkBuddy: "好的，跳过定价部分，
      继续完成其他章节，
      并在报告中标注'定价待补充'"
```

### 补充信息

提供执行过程中发现需要的信息：

```
WorkBuddy: "在分析过程中，我需要了解
      贵公司的主要竞品有哪些？"

用户: "主要竞品是 A 公司和 B 公司"

WorkBuddy: "收到，已将竞品信息纳入分析"

---

用户: "对了，补充一个信息：
      Q3 我们上线了 2.0 版本，
      这是重要的里程碑"

WorkBuddy: "已记录，会在报告的里程碑部分体现"
```

### 问题处理

遇到障碍时协商解决方案：

```
WorkBuddy: "在读取数据文件时遇到问题：
      sales_q3.xlsx 文件被其他程序占用，
      无法访问。
      
      建议方案：
      1. 关闭占用该文件的程序后重试
      2. 使用 sales_q3_backup.xlsx 替代
      3. 手动复制文件到其他位置
      
      请选择处理方式，或告诉我其他方案"

用户: "用备份文件就行"

WorkBuddy: "好的，切换到备份文件继续执行"
```

## 结果反馈与迭代

### 初步结果反馈

展示阶段性成果并征求意见：

```
WorkBuddy: "报告初稿已完成，主要内容包括：
      - 市场概述（2 页）
      - 竞争分析（3 页）
      - 趋势预测（2 页）
      
      预览：[链接]
      
      有任何需要调整的地方吗？"

用户: "竞争分析部分可以再深入一些，
      特别是差异化策略这块"

WorkBuddy: "好的，补充差异化策略分析..."
```

### 修改优化

根据反馈进行调整：

```
用户: "整体不错，但有几点修改：
      1. 开头的数据用最新的
      2. 第三部分太长了，精简到一页
      3. 加一个结论建议章节"

WorkBuddy: "收到 3 点修改：
      1. ✓ 更新开头数据
      2. ✓ 精简第三部分
      3. ✓ 新增结论建议
      
      正在处理，预计 5 分钟"
```

### 方向调整

大幅修改时明确新的方向：

```
用户: "这个方向可能不太对，
      我重新梳理一下需求..."

WorkBuddy: "好的，我来理解新的需求：
      从'面向投资者'调整为'面向内部团队'，
      重点从技术实现改为产品价值展示，
      是这样吗？"

用户: "是的，理解正确"

WorkBuddy: "收到，重新调整报告框架和内容方向..."
```

## 有效对话技巧

### 1. 明确具体

模糊的反馈 → 具体的指示

| 模糊表达 | 具体表达 |
|---------|---------|
| "不太对" | "第三部分的数据应该用 Q3 的而不是 Q2 的" |
| "再改改" | "语言可以更正式一些，像商务报告那样" |
| "缺东西" | "需要加上风险提示和应对建议" |

### 2. 提供示例

```
"第一部分的风格参考这个：
[粘贴示例文本]

后面的章节都按这个风格来写"
```

### 3. 优先排序

```
"有三处需要调整，按优先级：
1. （最重要）数据更新到本月
2. （其次）加上团队介绍章节
3. （可选）调整一下配色"
```

### 4. 确认理解

```
用户: "我觉得这个方向不太合适"

WorkBuddy: "我理解您希望调整方向。
      是因为：
      A. 目标受众需要变化？
      B. 内容侧重点需要调整？
      C. 整体框架需要重新设计？
      
      请告诉我具体是哪种情况，
      或者您的想法"
```

### 5. 保存偏好

```
用户: "以后这类报告都用这个格式"

WorkBuddy: "已记录您的偏好：
      标准报告格式 = 当前模板
      后续自动生成报告时将采用此格式"
```

## 对话中的指令

### 控制执行

```
"先停一下" - 暂停任务
"继续吧" - 恢复执行
"先取消这个" - 终止任务
"从头再来" - 重新开始
```

### 调整范围

```
"这部分可以跳过" - 删除某个步骤
"重点做这个" - 提升某部分优先级
"再加一个..." - 追加需求
"不用包含..." - 限定范围
```

### 质量要求

```
"可以再详细一些" - 增加深度
"精简一点" - 控制篇幅
"换个角度" - 调整视角
"这个数据需要核实" - 要求准确性
```

### 格式调整

```
"用表格展示" - 改变格式
"加上图表" - 增加可视化
"导出成 PDF" - 指定输出格式
"按照这个模板" - 指定样式
```

## 多轮对话示例

### 完整案例：周报生成

```
【第 1 轮：创建任务】
用户: "帮我生成本周工作周报"

WorkBuddy: "好的，为了准确生成周报，请问：
1. 周报是提交给哪位领导/团队？
2. 需要包含哪些重点内容？
3. 有特定的格式或模板要求吗？"

【第 2 轮：明确需求】
用户: "发给 CTO 的，重点写技术进展和遇到的问题，
      格式参考上周那份即可"

WorkBuddy: "明白了，技术进展 + 问题汇总，参考上周格式。
      开始读取工作记录..."

【第 3 轮：执行反馈】
WorkBuddy: "已读取工作记录，识别到以下关键内容：
      - 完成 API 接口优化（3 个）
      - 进行数据库性能调优
      - 遇到缓存一致性问题
      
      周报将包含这些要点，继续生成..."

【第 4 轮：中途调整】
用户: "对了，周三的技术分享会也写进去"

WorkBuddy: "收到，补充技术分享会内容..."

【第 5 轮：结果展示】
WorkBuddy: "周报初稿已完成，包含：
      - 本周技术进展（4 项）
      - 遇到的问题及解决（2 项）
      - 下周计划
      
      预览：[链接]
      有任何调整吗？"

【第 6 轮：最终确认】
用户: "挺好的，没问题了"

WorkBuddy: "周报已生成完毕，已保存到 ~/reports/weekly/
      您可以随时下载或分享"
```

## 常见问题

### Q: 对话太频繁会影响效率吗？

**A**: 适度对话能提升最终质量。建议：
- 简单任务：一次性描述清楚，减少干预
- 复杂任务：关键节点确认，避免方向偏差
- 不确定时：及时询问，好过事后返工

### Q: WorkBuddy 会忘记之前的对话吗？

**A**: 在同一任务中，WorkBuddy 会保持上下文记忆。但：
- 已完成的任务对话会归档
- 新建任务需要重新提供背景
- 重要偏好设置会被长期记忆

### Q: 可以用简短指令吗？

**A**: 可以。WorkBuddy 理解简洁表达：

```
"改改" → 理解为上次的修改方向
"继续" → 继续执行
"等等" → 暂停
"这个不要" → 删除当前处理的内容
```
